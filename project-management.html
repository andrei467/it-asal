Cambridge AS & A Level IT · Project Management

Project Management

This page covers the stages of the project life cycle, what project management software does, and the tools used to plan and track tasks — critical path method, PERT, Gantt charts and work breakdown structures.

Stages of the project life cycle 15.1

A well-managed project ensures deadlines are met, that the resources (people, equipment, facilities or funding) required to complete a project are available, and that each person knows the job they are meant to do.

The project management process is usually carried out in four main stages: project initiation, planning, execution and monitoring, and project close.

Figure 15.2: Project life cycle stages. Monitoring can send the project back to planning.

Project initiation

The start of a project sets the goals of the project. It defines what the project will do, and why there is a need for it. Several aspects are determined at this stage.

Objectives. Each project has set objectives, and each large objective may be split into smaller ones. For example, installing a new IT system for a business could be divided into:

  1. purchase the equipment
  2. prepare the building (cabling and power sources)
  3. install the new machines
  4. check that the machines work
  5. ensure users are satisfied

Each of these could be subdivided into even smaller objectives, and it is important to list all of them at the start. Every project has an owner, usually the person who wants the project completed (an external customer or an internal member of staff). The owner usually agrees to the objectives at the start, meaning they agree that all the objectives they want have been listed.

Resources. Resources may be items like new computers or cables, or people such as IT technicians or electricians. Time is also a resource. Resources usually cost money. Projects can run over time and money if all resources are not identified at the start, because more resources have to be bought later.

Success criteria are essential elements of the project that must be completed. They are not the same as goals. For installing an IT system they could include 'Must have enough machines for 150 people', 'Must use Windows OS' or 'Must have 2 monitors per machine'.

Stakeholders and their needs. Stakeholders are anyone who has an interest in the project, for example the user of the new IT system. They comment on the success criteria and say what they want from the project, so they can impact the goals and the success criteria.

Project scope and high-level schedules. Project scope defines how 'large' the project is. In big projects some tasks may be outsourced to other businesses. For example, connecting a new electricity supply to a building is done by the local electricity company, so it is 'out of scope'. A high-level project schedule sets out a rough plan of the tasks and how long they will take, based on the resources, goals and success criteria.

Project planning

Did you know?

There is a common phrase: "failing to prepare is preparing to fail". It means that if you do not plan something fully, it is most likely to fail.

Projects are planned so that all stakeholders know what to do during all stages. Budgets and schedules are created and milestones are set — dates by which each part of the project must be completed. Tasks for one milestone are done before the tasks of later milestones. A Gantt chart is produced to show the order in which tasks should be completed.

Resources are allocated to tasks and must be available when needed. The most important part of planning is making sure appropriate time is allocated to each task and the resources for each task are organised so tasks can be completed on time. It is wasteful to have resources not being used: you would not hire an electrician to install the software. Grouping an electrician's tasks into one milestone means they can be hired once to connect the power supply and fit all the wiring, instead of many times for short periods, which is inefficient and may cost more.

Project execution and monitoring

Implementing the plan. Once the plans are completed, a start date is set and the project starts. The execution is the 'doing' part, when the milestones are completed.

Monitoring progress against time. As each task is completed it is monitored, to check that each part is going to be completed on schedule. Following the plan closely helps make sure resources are used at the right times. Delays to tasks mean tasks scheduled later are delayed too.

Each project has a project manager, who informs each team member about their role, responsibilities and milestone dates, and is responsible for keeping the project to schedule. Projects are not always completed on time, often because smaller tasks take longer than planned, and each delay affects the next section so delays increase as the project moves forward. However, good monitoring can identify where delays may occur, letting the project manager re-plan small sections to keep the whole project on schedule. The project manager also monitors the performance of the team, compares expenditure against the budget, and ensures the scope does not grow beyond the agreed boundaries.

Cost and quality. The project manager checks that costs stay within the budget. Sometimes this is not possible: during the COVID-19 pandemic a shortage of processors made them much more expensive, so installing an IT system cost more. Cost increases must be discussed with stakeholders, and if the project becomes too expensive it may need to be cancelled. Costs can also go down, for example if a different electrician does the work for less.

A project is also monitored for quality: each task is checked to ensure it is completed well, for example that there are enough cables and they are installed correctly. This matters because it often costs more money and delays the project if mistakes are only noticed later in the life cycle.

Reporting to stakeholders. Stakeholders want to know how the project is progressing in terms of:

  • time
  • cost
  • delays
  • quality

During execution the project manager prepares reports for the stakeholders, so they can monitor progress and provide input if needed.

Project close

A handover happens between the project team and the client when the project is complete. The client reviews the project with the project manager, and if the client is happy that everything is finished as expected, they sign off the project as completed — meaning no further work is needed. Once signed off, any contracts with the workers are closed and any resources are released, so other people or projects can use them.

A review also takes place, looking at what went wrong and what went well. It covers questions such as:

  • Was the project schedule maintained?
  • Was the project completed within budget?
  • Were all resources available when required?
  • Has the project met the original requirements?

The review is stored and used to help plan future projects, so they avoid the same mistakes.

Project management software 15.2

Types of project management software

There are many different types, which can be used on different devices. Examples include Jira, Wrike, Miro and Monday, and Microsoft also produces Microsoft Project. Project management software is often run on a desktop computer or laptop, but some projects need it on mobile devices such as smart phones or tablets. Some is web-based, allowing management of projects across the globe, because people from different countries can log in and update projects.

Licensing

Licensing is the rules on how you can use software. Personal licences allow use on a home computer but not for work purposes for a business, which could be useful for a home project such as building a shed. Single-user licences can be used within an organisation but only one person can use the software at once. Collaborative project management software allows many people to log in at the same time, which is useful for large projects with many project managers and stakeholders.

Uses of project management software for supporting projects

Planning. It can schedule tasks to meet milestones and allocate resources to each task. It can link documents such as budgets, goals, requirements and resources to specific tasks, so users have the data they need to complete each task on schedule and within budget. It provides templates for the planning stage, used to set up initial plans and budgets. Templates from previous successful projects can be reused, so projects in an organisation have common, recognisable structures.

Scheduling of tasks. It can schedule and track the progress of tasks. A Gantt chart shows an overview of the tasks on a timeline, and lets a project manager assign hours or days and a deadline to each task; Gantt charts often sort or group tasks automatically. The manager can identify which tasks are dependent on other tasks (a task cannot start until another has been completed), delegate tasks to team members, and give tasks a priority so they can be sorted from most to least important. It also allows:

  • recording how many hours are spent on each task
  • marking each task as complete
  • creating milestones for crucial points
  • highlighting key project parts
  • producing a calendar of events, milestones and progress achieved

Allocation of resources. Resources (equipment, property or people) must be defined in the software, along with their availability, so the manager knows when each can be used. Each resource is given a cost and a number of hours or days it will be used for, so the manager can see how resource use affects the budget. This is very important when people are resources: if too many tasks are allocated to one person at once, they cannot complete them, may become stressed and rush, and tasks may not be completed to a good standard.

Costings. The cost of a task is based on how many hours each resource is used for and how much each costs per hour. The software also records extra expenses incurred by team members, adds them to the overall cost, and can track spending over different time periods, for example graphs of daily, weekly and monthly spending. It can report total costs for individual resources and export data to common file types such as .xlsx or .csv, so spreadsheet software can analyse it.

Communication and collaborative working

  • Calendars: each team member has one, showing the tasks they should be working on. They can be synchronised with third-party calendars such as Google, iCal or Outlook, so members can check them on mobile devices. Shared calendars let meetings be scheduled, with documents attached for review beforehand.
  • Instant messaging / video chat / video conferencing: real-time communication to share ideas and discuss progress, useful when team members work in different countries.
  • Shared documents: cloud storage acts as a central store accessible from anywhere. Documents can be assigned to tasks, resources or milestones, changes can be tracked, versions saved or restored, and team members emailed when documents change.
  • Discussions / forums: set up for tasks, documents or milestones. Very useful when team members are not in the same time zone; they can send email notifications and alerts to project dashboards.
  • Progress: team members update tasks to show how close they are to finishing, which feeds into the project plan. When the timeline changes, automated email notifications go to all affected team members.

Decisions and the critical path

Communication and decisions are usually recorded, so each decision can be linked to the person who made it and why. The software can highlight potential issues and suggest changes, such as changing the timeline or allocating more resources, and these issues can be monitored until resolved. It can compare the project plan with current progress, showing how much time was spent on a task compared with how much was planned, so lessons can be learned for similar tasks.

It also identifies the critical path — the tasks that must be completed on time for the project to complete on time. Critical paths are monitored closely and resources are diverted to critical tasks if they fall behind, helping the project meet its deadlines and recover lost time.

Advantages and disadvantages

Advantages

  • Can manage very large projects efficiently
  • Can produce a range of outputs to see how the project develops
  • Can automatically update areas of the project if changes are made to another part
  • Can send automated reminders and updates to people
  • Can be used to make calculations very quickly
  • Can analyse and make suggestions to help save money and time
  • Can reduce the number of people required to manage the project, making communication and control more effective
  • Stakeholders can use it for a summary of what stage the project has reached and any potential issues

Disadvantages

  • May be expensive to buy; many users need several licences, adding to the cost
  • The business may not afford the software most appropriate for its requirements
  • Special training is often needed, and may differ for different users
  • Can be difficult to set up, which could lead to inaccurate results later
  • Team members may rely too much on the software and not realise something is wrong if it raises no alert
  • Backups of the data need to be made in case of computer failure
  • Access and security levels must be set up properly so users can reach the information they need

Tools and techniques for project management tasks 15.3

There are three main tools and techniques used for project management tasks: the critical path method, the performance evaluation and review technique, and Gantt charts.

Critical path method (CPM)

A critical path identifies the order in which project tasks must be completed for the whole project to finish on time. It is also the minimum amount of time in which the project can be completed. The critical path method, also known as critical path analysis (CPA), can only be used when the length of each task is known. Project management software calculates the critical path, identifies the longest and shortest paths, and lists all the dependent tasks needed to achieve each path (a task that relies on another being completed before it can start).

Worked example 15.01: making a cup of tea. The circles are milestones, each with a unique number. The tasks are the arrows, and the numbers show how many seconds each takes, for example pouring water into the cup takes 10 seconds. The deliverable at the end is a cup of tea.

Figure 15.7: Network activity diagram for making a cup of tea. The critical path (gold) is 15 + 180 + 10 + 5 + 10 = 220 seconds; the three grey tasks run in parallel with boiling the kettle.

Some tasks can be completed in parallel. Boiling the kettle can take place at the same time as putting tea in the cup, sugar in the cup and getting milk out of the fridge. Where there are parallel tasks, the longest timeline forms the critical path: 180 seconds to boil the kettle is longer than the 60 seconds for the three parallel tasks. Sequential tasks cannot be done at the same time because they depend on other tasks completing first — boiling the kettle cannot start until the kettle is filled.

The length of the critical path is all the sequential tasks plus the longest of each parallel set: 15 + 180 + 10 + 5 + 10 = 220 seconds, the shortest time to complete the project. If any task on the critical path takes longer than planned, the end point is delayed.

Float time

Some tasks have float time — spare time before the next dependent task must start. A task with float can be delayed without affecting the rest of the project. In the tea example, getting milk out of the fridge has float: the tea (25 s), sugar (25 s) and milk (10 s) tasks take 60 seconds, while the kettle takes 180 seconds, leaving 180 − 60 = 120 seconds of float.

Earliest start, earliest finish and float

Network activity diagrams can be extended to include the earliest start time (ES) and earliest finish time (EF) of a task. The ES of the first task is 0 and its EF is the length of that task. The ES of all other tasks is the latest EF of its dependents:

ES of task = latest EF of dependents
EF = ES + length of task
Float time = ES of next task - EF of task

In Worked example 15.03, the EF for installing windows is day 30 but the EF for tiling the roof is day 42. Both are dependents of first fix electrics, so its ES must be day 42, which leaves 42 − 30 = 12 days of float for the windows. When working in days, the ES and EF are the beginning of the day: if the EF of task 2 is day 4, task 2 should be finished by the beginning of day 4, or the end of day 3.

Crashing

A network activity diagram helps allocate the right resources to a task. Additional resources can be allocated to a task that needs to finish earlier than planned — this is known as crashing. Resources can be moved from tasks with high float times, because it is not critical that those tasks finish at their earliest possible time. If resources cannot be taken from float tasks, additional resources incur additional cost, which increases the project budget. For example, building the roof earlier could use resources from the plumbing task, which has 12 days of float.

Advantages and disadvantages of CPM

Advantages

  • Creates critical paths of shortest and longest options
  • Lists resources needed
  • Gives total times
  • Can show float times
  • Shows dependent activities

Disadvantages

  • Must have all times for task completion
  • Must know all dependent activities

Performance evaluation and review technique (PERT)

PERT is used to plan, schedule and manage project tasks. It can also identify a critical path. PERT is more suitable for research and development projects or non-repetitive projects, because it uses estimates of time for tasks, not actual times. Tasks are represented by arrows and milestones by circles (also called nodes), so PERT and network activity diagrams use similar symbols and can look very similar.

Tip: PERT uses estimated time for tasks; CPM uses actual time for tasks.

PERT estimates the time for a task using three values:

EstimateWhat it assumes
Most optimistic timeEverything will go right and no problems will occur
Most likely timeA prediction based on what may or may not go wrong, and the chances of that happening
Most pessimistic timeAnything that can go wrong will go wrong

Advantages

  • Creates critical paths
  • Not all timings need to be as precise or known
  • Uses estimated times
  • Gives a range of times for completion (optimistic, likely, pessimistic)

Disadvantages

  • Uses average times
  • Must know all dependent activities

Gantt charts

A Gantt chart shows the start and finish dates of each task, the dependents of each task, the progress of each task and the current position within the project. Each bar is a task, and can be shaded to show the percentage completed. Arrows show which tasks depend on others, and a line can show the current time. It is also possible to identify the resources required. To create one you need:

  • the list of tasks
  • how long each task will take
  • which tasks are dependent upon others
  • the start date of the first task
  • the resources allocated to each task

Some programs that create Gantt charts (such as GanttProject) only work in days or months, so you may need to convert hours to days, for example a task of 6 hours converts to 0.25 days.

  • Shows dependencies
  • Each row is a task, which helps to track tasks more easily
  • Progress can be clearly tracked with how complete each task is

Disadvantages

  • Must know how long each task will take, which tasks have dependents, the start date of the first task and the resources allocated to each task
  • May need to convert time into hours or minutes, which can be confusing and make it harder to read

Work breakdown structure (WBS)

All the tools so far break the project into manageable tasks. But very large projects may contain hundreds of tasks at once, which can be very difficult to interpret and may create anxiety for team members. To help manage them, a hierarchical decomposition of the project can be created as a work breakdown structure (WBS): a hierarchical diagram with tasks allocated to sub-tasks or project phases.

In a software development project, the project might be broken down into the stages of a development life cycle. A project manager would then be responsible for each stage, for example the testing stage, and each stage would be broken down further into the phases involved.
