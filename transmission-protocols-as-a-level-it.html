Cambridge AS & A Level IT · Chapter 14 Communications Technology

Transmission & Protocols

How data actually moves across a network: bandwidth and streaming, how packets are routed, the protocols devices use to agree on the rules, how routers manage traffic, and the physical media data travels along.

Data transmission across networks 14.5

Bandwidth

Bandwidth is the range of frequencies available to a communication method, which determines its transmission rate — the maximum amount of data that could be transferred across a network in a given time (usually one second). The more bandwidth a connection has, the more data it can transfer at once. It's often measured in Hertz (Hz).

Bandwidth isn't the same as speed: bandwidth is the potential capacity, while speed is the actual transfer rate a user experiences, which is also affected by factors such as latency and the efficiency of the device.

Bit rate

Bit rate is the rate at which bits are actually transferred in a given period of time, usually in bits per second (bps) or a multiple such as kilobits per second (Kbps). A transfer's bit rate can never exceed the bandwidth available, since bandwidth is the maximum possible bit rate.

Real-time and on-demand streaming

There are two types of media streaming. In real-time streaming, data is streamed as soon as it's recorded, for example by a camera. In on-demand streaming, data is pre-recorded and streamed to the user whenever they request it.

Streaming removes the need to download and store a whole file before viewing or listening to it. Data arrives as a series of bits and is held in a temporary storage area called a buffer: it's stored in the buffer as it downloads, then removed to be played while more data is simultaneously added, ready for when it's needed.

Available bandwidth limits the quality of video or audio that can be streamed — a connection with only 2 Mbps of bandwidth, for example, is highly unlikely to stream a 4K movie, because producing each frame needs far more data than that bandwidth can carry.

How bit rate and bandwidth affect streaming quality

  • Bit rate represents how much data is stored per unit of time in the streamed video
  • The bandwidth of the connection determines the bit rate that can actually be used
  • If the connection doesn't have enough bandwidth for the required bit rate, the video stalls, becomes jerky, or has to keep buffering, harming the viewer's experience
  • Video can be sampled or compressed at different bit rates — a lower bit rate produces video that lacks detail, looks pixelated, or shows jerky motion
  • The more bits used, the higher the quality

Routing data in networks 14.6

Structure of a data packet

A data packet is normally the smallest unit of data sent across a network, and its exact contents depend on the network it's travelling over — a packet sent over the internet, for example, needs more information to be directed to the right place. A packet typically has three parts: a header, a payload and a trailer.

PartWhat it can contain
HeaderThe sender's IP address (the source IP address); the receiving device's IP address (the destination IP address); a sequence number, so packets can be reordered at the receiving end; the MAC addresses of the sender and receiver (removed once the packet passes through a router, since MAC addresses are only used by switches); and any protocols used.
PayloadThe actual data from the file being transmitted.
TrailerA flag marking the end of the packet, and any error-checking information.

The header and trailer exist to make sure the payload data arrives at its intended destination without errors.

Packet switching

In packet switching, a message is divided into smaller units — data packets — which are each given a unique sequence number and sent individually. Every packet's header carries information such as the source address, destination address and sequence number. Packets travel from router to router, each taking whatever path the router judges shortest at that moment, so different packets from the same message can take different routes and arrive at different times. They are reassembled in the correct order at the receiving end; if a packet is missing or corrupted, a message is sent asking for it to be resent, and once all packets have arrived correctly an acknowledgment is sent back.

There are two main methods of packet switching: connection-oriented (also called virtual circuit switching) and connectionless (also called datagram switching).

Connection-oriented switching

A session is created before any data is transferred, forming a fixed channel for the data to travel along. The first packet sent includes a request for acknowledgment; if the acknowledgment is received, the sender transmits further packets, and if not, it tries again with the first packet. Frame relay and TCP are both connection-oriented.

MethodHow it works
Frame relayData is separated into units called frames. Error correction is handled by the devices at each end of the transmission, which speeds things up. If an error is detected in a frame, that frame is simply dropped, and the endpoint devices detect the gap and request a retransmission — making frame relay best suited to situations where errors are likely to be rare. It uses permanent virtual circuits (PVCs), intended to exist for long periods even when no data is being sent, or switched virtual circuits (SVCs), temporary connections that exist only for a single session.
TCP (Transmission Control Protocol)A connection is created and kept open until the applications at each end have finished exchanging data. TCP decides how data is broken into packets, handing them to (and receiving them from) the network layer in the TCP/IP model. It is responsible for error-free transmission and for managing the flow of data.

Connectionless switching

There's no prior arrangement between devices before data is sent — packets are simply dispatched, with no way to know whether the receiver is ready, and no way to confirm the transmission succeeded. Ethernet, IP and UDP are all connectionless.

MethodHow it works
EthernetA long-established protocol for connecting devices over a wired connection, making sure devices on the network format and transmit data in a way others will understand. Most home and school networks use Ethernet.
IP (Internet Protocol)The protocol used when data is sent across the internet, responsible for delivering packets of data to the receiving device.
UDP (User Datagram Protocol)An alternative to TCP. It sends data in units called datagrams, and — unlike TCP — doesn't control the flow of data or carry out error checking. This makes exchanging data with UDP generally faster than with TCP, though less reliable.

Circuit switching

Circuit switching establishes a dedicated path between sender and receiver before any communication takes place — rather like how a traditional telephone call works. Once a connection is established, that dedicated path remains in use until the connection ends, and no other device can use that same path while it's active.

Steps: the sender identifies the intended receiver; the system checks whether the receiver is ready; if so, a sequence of links is established across the network; the data is transferred; and finally the links are taken down. Circuit switching is used in the public telephone network, mainly for voice transmission, and only a fixed amount of data can be transferred at a time.

Message switching

In message switching, a complete message is treated as a single unit and routed through intermediate nodes, where it's stored and then forwarded — a store-and-forward approach. No dedicated path is set up between sender and receiver in advance; instead, the destination address is attached to the message, and each node stores the whole message before forwarding it on, choosing what it judges to be the most efficient route at that point (a form of dynamic routing). Each message is treated as an independent entity.

IP addressing

An IP address identifies a device's location on a network, or uniquely identifies it on the internet. IP addresses can be IPv4 (32 bits long) or IPv6 (128 bits long), and can be static (stays the same every time the device reconnects) or dynamic (changes each session) — most devices use a dynamic address unless the user specifically requests a static one from their internet provider.

MAC addressing

A MAC address identifies a device on a network via its NIC. It sits at the data link layer (layer 2) of the OSI model, and matters for communication within the local network: it lets routers identify devices within the same network segment so they can forward data correctly. The Address Resolution Protocol (ARP) relies on MAC addresses to map IP addresses within the local network. Because each MAC address is unique — made up of a manufacturer ID and the device's own serial number — there's no duplication or address conflict. In wireless networks, MAC addresses also help with access control and filtering, letting administrators permit or block specific devices.

Network protocols 14.7

A protocol is a set of rules for sending and receiving data between devices on a network. Protocols define the format, timing, sequencing and error checking of data exchanged, so devices from different manufacturers can communicate seamlessly.

ProtocolWhat it does
TCP (Transmission Control Protocol)Sends data as datagrams over IP, in connection-oriented, point-to-point communication. Provides checksums and port numbers for the source/destination, reports lost or damaged packets back to the sender, manages flow control, and uses handshaking to establish a connection. Used whenever reliable delivery matters.
IP (Internet Protocol)Lets different devices communicate over the internet, giving each one a unique address and ensuring packets are routed correctly. Takes a packet from the transport layer, adds its own header (with sender and recipient IP addresses), encapsulates the data into a datagram, and passes it to the link layer for transmission.
ICMP (Internet Control Message Protocol)An error-reporting protocol that generates error messages back to the sender when network problems prevent data packets being delivered.
ARP (Address Resolution Protocol)Translates an IP address into a MAC address for a device, bridging the network layer and the data link layer of the OSI model.
IARP (Inverse Address Resolution Protocol)The reverse of ARP: translates a MAC address into an IP address.
DHCP (Dynamic Host Configuration Protocol)A network management protocol that automatically assigns IP addresses, a gateway address and a subnet mask to devices on a network, keeping a database to avoid addressing conflicts.
UDP (User Datagram Protocol)Sends data as datagrams over IP, like TCP, but for connectionless communication: no reporting of lost packets, no handshaking, no guarantee of delivery or order, and no error checking. Used when speed matters more than guaranteed delivery, avoiding the overhead of error checking.
HTTP / HTTPSHTTP transfers web page content from a server to a browser. HTTPS adds security, encrypting data using TLS/SSL, authenticating the website with a public-key certificate, restricting access to authorised users, and protecting against eavesdropping, man-in-the-middle attacks, and the alteration or insertion of malicious code into a site.
FTP (File Transfer Protocol)Responsible for transferring files between a client and a server on a network.
Tunnelling protocolUsed for secure data transmission across networks. Encapsulates private data packets so they look like ordinary public packets, letting them travel across a public network (data may be further encrypted with SSH or IPSec). Important for VPNs, and can also let a network use a protocol it wouldn't otherwise support, such as IPv6 over an IPv4 network.
SMTP (Simple Mail Transfer Protocol)Sends email from a computer to a mail server, and between different mail servers.
POP (Post Office Protocol, e.g. POP3)Retrieves email from a mail server: when the user checks their mailbox, the email is downloaded to their device and then deleted from the server.
IMAP (Internet Message Access Protocol)Also retrieves email from a mail server, but — unlike POP — doesn't delete it from the server automatically; the email stays there until the user chooses to delete it.
TelnetLets a user connect remotely to another computer over the internet, but sends data in plain text with no authentication or encryption, making it insecure and largely replaced by SSH.
SSH (Secure Shell)Gives secure access to a computer over an unsecured network, encrypting data end-to-end between applications. Uses a client-server model, works at the application layer, and uses automatically generated public/private key pairs so an observer can't make sense of intercepted data.
TLS/SSLDesigned to secure connections between web clients and web/mail servers, using both public and private keys to encrypt data in transit. TLS is the updated version of SSL, using newer, more secure encryption algorithms.

Managing network traffic 14.8

Routing

Routing is the process of working out the route data packets should take, and happens at the network layer of the OSI model. Routers use it to decide the next hop to send a packet to. Routing algorithms build a routing (forwarding) table, stored in the router's non-volatile memory, used to choose the preferred route. There are two types: static and dynamic, and both provide a default route for a packet if no specific route can be found.

TypeKey features
Static routingRoutes are entered into the router by a network administrator, and stay fixed — they aren't configured automatically. Defines a 'route of last resort' (where to send a packet if no destination is known), and provides a fail-safe if dynamic routing can't find a route. Can also be used to transfer routing information from one routing protocol to another.
Dynamic routingRouting protocols build the table automatically, from the real-time state of the network, rather than a human entering it. Routing information can be shared automatically with other routers using the same protocol, to discover remote networks or changes. Can limit how many hops a packet may take, give each route a 'time to live' after which the table is refreshed, reroute packets around network issues or a failed router, and keep as many alternative routes open as possible.

Routing protocols

Routers use routing protocols to decide how to communicate with each other and select the route data should travel. There are three main types:

Protocol typeRole
Interior gateway protocolSpecifies how routers communicate within a single network, such as a LAN.
Exterior gateway protocolSpecifies how routers communicate between different networks.
Border gateway protocolA specific kind of exterior gateway protocol managing the exchange of data across the largest network of all: the internet.

The OSI model

The OSI model describes networking as seven layers, each handling a specific function:

LayerFunction
ApplicationThe top layer, interacting directly with user data. Applications such as web browsers and email clients rely on it (though end-user software like a word processor isn't part of this layer itself). Manages protocols such as HTTP and SMTP.
PresentationPrepares data for the application layer — translating, encrypting/decrypting and compressing/decompressing it as needed, so it's understood by the receiving device and transmitted efficiently.
SessionOpens and closes the communication link (the 'session') between devices, keeping it open just long enough for all the data to be transmitted before closing it.
TransportBreaks data from the session layer into segments, hands them to the network layer, and reassembles them at the receiving end. Also handles flow control and error checking, requesting retransmission if data is incomplete.
NetworkBreaks transport-layer segments into smaller units called packets, and reassembles them after transmission. Handles routing — finding the best path across the network — when data moves from network to network. The router is a key device at this layer.
Data linkSimilar to the network layer, but for transmitting data from node to node within one network rather than between networks. Converts packets into frames. The switch is a key device at this layer.
PhysicalThe physical equipment used to transmit data, such as cables. Breaks data down into bits for transmission as binary, and reassembles bits into frames after transmission.

The TCP/IP model

LayerFunction
Application layerCondenses the OSI model's application, presentation and session layers into one. Uses protocols such as HTTP, SMTP, POP and FTP for a standardised exchange of data.
Transport layerComparable to the OSI transport layer: maintains end-to-end communication between devices, mainly using TCP or UDP.
Network (internet) layerComparable to the OSI network layer: breaks data into packets and moves it from network to network, mainly using IP or ICMP.
Link layerAlso called the physical layer; condenses the OSI model's data link and physical layers. Uses protocols such as ARP.

OSI vs TCP/IP

What they share

  • Both use a logical, layered framework for defining and implementing network standards
  • Each layer in both models only defines a specific set of functions
  • Both divide complex functionality into simpler sections, making network behaviour easier to understand
  • Both reference existing standards and let manufacturers build interoperable devices and components

How they differ

  • The OSI model has seven layers; the TCP/IP model has four (or five, depending on how it's described) — more layers overall in OSI
  • OSI splits application-level functions into three separate layers, where TCP/IP uses just one combined application layer
  • OSI keeps the physical and data link layers separate; TCP/IP combines them into a single link layer
  • The OSI network layer supports both connection-oriented and connectionless links; the TCP/IP network layer only supports connectionless
  • The OSI transport layer only supports connection-oriented links; the TCP/IP transport layer supports both
  • The OSI transport layer guarantees delivery of packets; the TCP/IP transport layer doesn't
