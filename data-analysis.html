Data Analysis

This page covers how to clean and transform data in a spreadsheet, how to display it to communicate information, and how to organise data from different sources so it can be used in a database.

Transforming and cleaning data 17.1

If the answers provided by processing the data are to be relied on, the data they are based on must be accurate and in a format that can be analysed. There is a saying that if you put garbage in, you will get garbage out.

Figure 17.2 redrawn: if the data put in is not accurate and correctly formatted, the information that comes out cannot be relied on.

A visual inspection of the data can highlight obvious problems such as missing data, dates that are formatted incorrectly, numbers formatted as text, or a percentage given as a number rather than formatted as a percentage.

The spreadsheet in Figure 17.3 has inconsistencies that must be corrected before meaningful information can be extracted:

  • There are extra spaces before, in the middle of and after the employee names.
  • There are inconsistencies in the Hire Date column, with most in dd/mm/yyyy format and some in mm/dd/yyyy format.
  • The Annual Salary column is formatted as text and so could not be used in calculations.
  • The bonus percentage is given as a number rather than a percentage.
  • There are duplicates in the data.

Correcting these inconsistencies so that the data can be analysed and displayed is called cleaning, part of the transforming process. Transforming is converting data from one format or structure to another, to make it more suitable for analysis or processing. Cleaning involves identifying and resolving issues such as missing values, duplicates, errors, inconsistencies and formatting problems in the data.

Finding duplicates and reformatting data can be difficult just by looking at the spreadsheet, so spreadsheet functions and tools can be used to:

  • delete extra spaces
  • convert all dates to the same format
  • format numbers as a currency or percentage
  • remove duplicates

Deleting extra spaces

Instead of going into each cell and removing the extra spaces before, in the middle of and after the employee names, the TRIM() function does the same task. It cannot be done in the Full Name column itself, because a function is needed, so the function is added to an empty column, using data from the Full Name column.

  1. In cell J2, enter the formula =TRIM(B2). This removes the extra spaces in the name in cell B2 and copies it into J2.
  2. Copy the formula to the end of the column, so TRIM() removes the extra spaces from all the names in column B and writes them in column J.
  3. Paste the corrected names in column J back into column B by copying them and pasting them as values using Paste Special.
  4. Delete the names in column J.

Converting all dates to the same format

Most of the dates in the spreadsheet are in the UK format of dd/mm/yyyy, but some are in the US format of mm/dd/yyyy. These appear as text and are aligned to the left. They need to be changed to the UK format.

  1. Sort the data according to Hire Date in descending order. This separates the US-format dates from the UK-formatted dates so they can be reformatted; the dates in a different format sit at the top of the column and are formatted as text.
  2. Highlight the US-formatted dates and select Text to Columns in the Data ribbon.
  3. Select Delimited and make sure all the delimiters are deselected, then click Next.
  4. In the next window, select MDY as the date format of the dates to be reformatted to the UK format.
  5. Click Finish and the dates are converted to the correct format.

Formatting the Annual Salary column as currency

The Annual Salary column is formatted as text even though it has the $ sign, so it cannot be used in calculations. It can be reformatted as currency using Text to Columns.

  1. Highlight all of column F, but not the Annual Salary column heading, and select Text to Columns, then select Fixed Width.
  2. Select Next and move the delimiter line so that it is just after the $ sign. This is where the text will be split.
  3. In the next window, set the destination to J2.
  4. Select Finish: column J will contain the $ signs and column K the numbers.
  5. Format the numbers in column K as currency, then copy and paste them back into column F, overwriting the data.
  6. Delete the data in columns J and K.

Formatting the Bonus column as percentage

The data in column G is formatted as numbers rather than percentages, and will give inaccurate results when trying to work out how much bonus an employee has earned.

  1. Enter 1% into any free cell and copy this cell.
  2. Highlight the data in column G and select Paste Special.
  3. Select multiply as the operation and click OK.
  4. The numbers in column G are now formatted as percentages.

Removing duplicates

There are only 44 records in the spreadsheet, but there could be thousands, and it would be impossible to find duplicates by just looking through the data. The Employee ID column is the only one that should contain unique data, identifying a particular employee, so it is the column to check to see whether an employee has been included more than once.

  1. Highlight all the data in the spreadsheet and select Remove Duplicates in the Data ribbon.
  2. Select Employee ID as the column to check, then click OK.
  3. You are advised that three duplicates have been removed and 41 unique values remain.

Once data has been transformed and cleaned, it is ready for analysis and visualisation.

Displaying data to communicate information 17.2

There are various ways of analysing data and displaying the results, including pivot tables and pivot charts (covered in Chapter 8). Specific data may be highlighted using conditional formatting. Functions such as COUNTIF and COUNTIFS can also be used to create summaries of the data, which can then be displayed as charts and graphs.

Activity 17.09: analyse and visualise the clean employee data

Using the cleaned employee data, the data is analysed and visualised in these ways:

  1. Conditional formatting is added so that the data of Brazil is highlighted when the name is written into cell J2. The whole row must be highlighted, not just the country cells.
  2. In case users misspell a country name, a list box is added where they can select a country name.
  3. A worksheet named Information is created to analyse and visualise the data using the COUNTIFS function and pivot tables and charts.

The tables and charts on the Information worksheet should show:

  • the salary ranges of employees of different ages
  • the employees from different countries working in the different departments of the company

Getting data from different sources 17.3

Often, the data to be analysed and displayed may come from different sources and may need to be organised before it can be used. For example, the data may need to be split into fields so that it can be imported and merged.

If the data is being imported into a database, you need to consider the fields and tables required so that the database can be normalised to third normal form (3NF). Data held in a csv or spreadsheet file does not have to follow the rules imposed on databases, and there may be repeating and redundant data. The database will require key fields, and suitable ones may need to be added.

Activity 17.10: cat rescue centre

A cat rescue centre holds data about the cats it has and the people who adopt them. It has used a spreadsheet to store its data but now wants to use a database, because:

  • data is being repeated in the spreadsheet when the same person adopts several cats
  • a cat may be returned to the centre if the adoption is not successful, and so could be adopted several times

All cats are checked to see whether they have a microchip and, if not, one is inserted. Each microchip has a unique identification number. The database should allow data about new cats and owners to be entered, as well as importing the existing data. To make it relational, extra fields may be needed.

One possible design for Activity 17.10, based on the notes: a cat can be adopted several times, and a person can adopt several cats, so adoptions sit in their own table linked by keys. The activity asks you to design the real fields yourself.

The activity steps are:

  1. Using the data, create the fields and tables required for a relational database normalised to 3NF.
  2. Import the data from the spreadsheet into the appropriate tables.
  3. Create forms to display the data about the cats, the customers and the adoptions and allow new data to be entered.
  4. Access these forms from a main switchboard form.
  5. Open the other forms by clicking command buttons, as pop-up forms.
  6. The adoptions form should have the cats and customers forms as sub-forms, but they must be protected so that they cannot be edited when they are sub-forms.
  7. When a new adoption record is being created, the user should be able to select the customer and cat from drop-down lists.
